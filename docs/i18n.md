# i18n Reference — VoltLine

Reference for adding multi-language support to the VoltLine site. Stack: Next.js 16 (App Router) + React 19 + TypeScript.

## Decisions (locked)

| Topic | Decision |
| --- | --- |
| Library | **next-intl** |
| Locales | `sr-Latn` (default), `en`, `ru` |
| Default locale | Serbian, Latin script |
| URL strategy | Path prefix on every locale: `/sr/...`, `/en/...`, `/ru/...` |
| File layout | One JSON per locale: `messages/sr.json`, `messages/en.json`, `messages/ru.json` |
| Translation workflow | Manual JSON editing in git. No external TMS. |
| Plural/gender | ICU MessageFormat via next-intl |
| SEO | hreflang `<link>` tags, localized sitemap, per-locale metadata |
| Locale detection | Middleware-based: cookie → Accept-Language → default (`sr-Latn`) |

The site name "VoltLine" stays untranslated. Phone, address, and currency formats stay Serbian regardless of UI language.

### `src/i18n/routing.ts`

```ts
import { defineRouting } from "next-intl/routing";

export const routing = defineRouting({
  locales: ["sr", "en", "ru"] as const,
  defaultLocale: "sr",
  localePrefix: "always", // /sr/..., /en/..., /ru/...
  localeDetection: true,  // honors Accept-Language on first visit
});

export type Locale = (typeof routing.locales)[number];
```

> We use the simple tag `sr` in the URL (not `sr-Latn`) for cleaner paths. The full BCP-47 tag `sr-Latn` is used only when calling `Intl.*` formatters and in `<html lang>`.

### `src/i18n/navigation.ts`

```ts
import { createNavigation } from "next-intl/navigation";
import { routing } from "./routing";

export const { Link, redirect, usePathname, useRouter, getPathname } =
  createNavigation(routing);
```

Use these wrappers everywhere instead of `next/link` and `next/navigation` so links automatically carry the active locale.

### `src/i18n/request.ts`

```ts
import { getRequestConfig } from "next-intl/server";
import { hasLocale } from "next-intl";
import { routing } from "./routing";

export default getRequestConfig(async ({ requestLocale }) => {
  const requested = await requestLocale;
  const locale = hasLocale(routing.locales, requested)
    ? requested
    : routing.defaultLocale;

  return {
    locale,
    messages: (await import(`../../messages/${locale}.json`)).default,
    timeZone: "Europe/Belgrade",
    now: new Date(),
  };
});
```

### Root `src/app/[locale]/layout.tsx`

```tsx
import { NextIntlClientProvider, hasLocale } from "next-intl";
import { setRequestLocale } from "next-intl/server";
import { notFound } from "next/navigation";
import { routing } from "@/i18n/routing";

export function generateStaticParams() {
  return routing.locales.map((locale) => ({ locale }));
}

export default async function LocaleLayout({
  children,
  params,
}: {
  children: React.ReactNode;
  params: Promise<{ locale: string }>;
}) {
  const { locale } = await params;
  if (!hasLocale(routing.locales, locale)) notFound();
  setRequestLocale(locale);

  // Map URL locale -> BCP-47 for <html lang>
  const htmlLang = locale === "sr" ? "sr-Latn" : locale;

  return (
    <html lang={htmlLang}>
      <body>
        <NextIntlClientProvider>{children}</NextIntlClientProvider>
      </body>
    </html>
  );
}
```

> The current `src/app/layout.tsx` becomes `src/app/[locale]/layout.tsx`. Keep a tiny root `src/app/layout.tsx` that just renders `{children}` if any non-locale routes exist (e.g. `/api`).

### Plural rules cheat sheet

CLDR plural categories used by each locale (this is what ICU `plural` switches on):

| Locale | Categories | Notes |
| --- | --- | --- |
| `sr` | `one`, `few`, `other` | `one`: 1, 21, 31… ending in 1 (not 11). `few`: 2–4, 22–24… ending in 2–4 (not 12–14). `other`: rest. |
| `ru` | `one`, `few`, `many`, `other` | Same numeric breakdown as Serbian, plus `many` for 0, 5–20, etc. **Always include all four.** |
| `en` | `one`, `other` | Trivial. |

Always include `other` — it's the required fallback. If you write only `one` in Russian, ICU falls back to `other` for `few`/`many` and the result reads wrong.

### Naming conventions

- Top-level key = component or page section (PascalCase): `Hero`, `Nav`, `Blog`.
- Leaf key = camelCase string identifier.
- Avoid sentence keys (`"Click here to call"`) — use intent-based keys (`"cta"`).
- Don't concatenate translations in code. One key per full sentence. Use ICU placeholders for variables.

### Server components (preferred)

```tsx
import { getTranslations } from "next-intl/server";

export default async function Hero() {
  const t = await getTranslations("Hero");
  return (
    <section>
      <h1>{t("tagline")}</h1>
      <a href="tel:+381600000000">{t("cta")}</a>
    </section>
  );

```

### Client components

```tsx
"use client";
import { useTranslations } from "next-intl";

export function CallButton() {
  const t = useTranslations("Hero");
```

## 4. Date and number formatting

Always use next-intl's helpers (or `Intl.*` directly) — never `toLocaleString()` without a locale argument, and never hardcode separators.

### In components

```tsx
import { useFormatter } from "next-intl";

const format = useFormatter();
format.dateTime(post.date, { year: "numeric", month: "long", day: "numeric" });
format.number(2300);                             // 2.300 (sr/ru), 2,300 (en)
format.number(0.21, { style: "percent" });       // 21 % (sr/ru), 21% (en)
format.relativeTime(post.date);                  // "pre 3 dana", "3 days ago"
```

### Locale tags for formatters

next-intl uses the URL locale (`sr` / `en` / `ru`) by default. To get correct Serbian Latin separators, pass the BCP-47 tag explicitly when using `Intl.*` directly:

```ts
new Intl.NumberFormat("sr-Latn").format(1234.5);  // "1.234,5"
new Intl.DateTimeFormat("sr-Latn", { dateStyle: "long" }).format(new Date());
```

Configure this once in `src/i18n/request.ts` if you want next-intl helpers to use `sr-Latn` for `sr`:

```ts
return {
  locale,
  messages: ...,
  timeZone: "Europe/Belgrade",
  formats: {
    // shared format presets, optional
  },
  // Override the locale used by Intl.* — separate from the URL locale
  ...(locale === "sr" && { /* nothing needed, "sr" already implies Latin in modern ICU; verify in tests */ }),
};
```

In practice modern ICU treats bare `sr` as `sr-Latn` already; if you ever introduce Cyrillic, switch the URL locales to `sr-Latn` and `sr-Cyrl` instead of overriding here.

### Currency

VoltLine prices are in RSD. Currency stays RSD for all UI languages — only the formatting changes:

```tsx
format.number(5000, { style: "currency", currency: "RSD" });
// sr: "5.000 RSD"
// en: "RSD 5,000"
// ru: "5 000 RSD"
```

Don't convert to USD/EUR/RUB automatically. If the business decides to show converted prices later, add a separate "display currency" preference — that's a product decision, not an i18n one.

## 5. SEO

### Per-page metadata

Replace static `metadata` exports with `generateMetadata` that reads translations:

```tsx
// src/app/[locale]/page.tsx
import { getTranslations } from "next-intl/server";
import type { Metadata } from "next";

export async function generateMetadata({
  params,
}: {
  params: Promise<{ locale: string }>;
}): Promise<Metadata> {
  const { locale } = await params;
  const t = await getTranslations({ locale, namespace: "Meta.Home" });

  return {
    title: t("title"),
    description: t("description"),
    alternates: {
      canonical: `/${locale}`,
      languages: {
        sr: "/sr",
        en: "/en",
        ru: "/ru",
        "x-default": "/sr",
      },
    },
    openGraph: {
      locale: locale === "sr" ? "sr_RS" : locale === "ru" ? "ru_RU" : "en_US",
      alternateLocale: ["sr_RS", "en_US", "ru_RU"].filter(
        (l) => !l.startsWith(locale),
      ),
    },
  };
}
```

### hreflang

Set `alternates.languages` on every page (homepage, blog index, each blog post). The `x-default` should point to the Serbian version since `sr` is the source/default. Google uses these for cross-locale ranking.

### Sitemap

`src/app/[locale]/sitemap.ts` should emit one entry per locale × URL, with `alternates` set:

```ts
import type { MetadataRoute } from "next";
import { getAllPosts } from "@/lib/blog";
import { site } from "@/lib/site-config";
import { routing } from "@/i18n/routing";

const localizedPath = (locale: string, path: string) =>
  `${site.url}/${locale}${path === "/" ? "" : path}`;

const buildAlternates = (path: string) => ({
  languages: Object.fromEntries(
    routing.locales.map((l) => [l, localizedPath(l, path)]),
  ),
});

export default function sitemap(): MetadataRoute.Sitemap {
  const now = new Date();
  const paths = ["/", "/blog", ...getAllPosts().map((p) => `/blog/${p.slug}`)];

  return paths.flatMap((path) =>
    routing.locales.map((locale) => ({
      url: localizedPath(locale, path),
      lastModified: now,
      changeFrequency: "weekly" as const,
      priority: path === "/" ? 1 : 0.6,
      alternates: buildAlternates(path),
    })),
  );
}
```

Note: as of Next 15+, `MetadataRoute.Sitemap` supports `alternates.languages`. If your Next version doesn't, generate a custom XML route at `/sitemap.xml/route.ts`.

### robots.ts

Stays at root (no locale prefix needed) and just points at `/sitemap.xml`.

### structured data

`LocalBusiness` JSON-LD should appear on every locale's homepage. The `name`, `address`, and `telephone` stay identical across locales; only `description` and `areaServed` translate.

## 6. Locale switcher

The switcher must preserve the current pathname. Use the typed `usePathname` from `next-intl/navigation` so it returns the path **without** the locale prefix.

```tsx
"use client";
import { useLocale, useTranslations } from "next-intl";
import { usePathname, useRouter } from "@/i18n/navigation";
import { routing } from "@/i18n/routing";
import { useTransition } from "react";

export function LocaleSwitcher() {
  const t = useTranslations("LocaleSwitcher");
  const locale = useLocale();
  const pathname = usePathname();
  const router = useRouter();
  const [isPending, startTransition] = useTransition();

  return (
    <select
      aria-label={t("label")}
      defaultValue={locale}
      disabled={isPending}
      onChange={(e) => {
        const next = e.target.value as (typeof routing.locales)[number];
        startTransition(() => router.replace(pathname, { locale: next }));
      }}
    >
      {routing.locales.map((l) => (
        <option key={l} value={l}>
          {t(l)}
        </option>
      ))}
    </select>
  );
}
```

UX rules:
- Switching locale should **not** reload to the homepage. Always preserve `pathname`.
- The switcher updates `NEXT_LOCALE` cookie automatically (via `router.replace` with `locale`), so the user's choice persists.
- For accessibility: label the control and use full language names in their **own** language (`Srpski`, `English`, `Русский`), not in the currently active language. Update `LocaleSwitcher.{sr,en,ru}` keys accordingly if you adopt this — the doc above shows them translated, which is also valid; pick one and be consistent.

## 7. Locale detection (middleware)

`createMiddleware(routing)` does this out of the box:

1. If the path already has a locale prefix (`/en/...`), it's used.
2. Else if the `NEXT_LOCALE` cookie is set and valid, redirect to that locale's URL.
3. Else parse `Accept-Language`, pick the best match from `["sr", "en", "ru"]`.
4. Else fall back to `defaultLocale` (`sr`).

A user from Russia hitting `/` gets redirected to `/ru`. A user from Serbia or anywhere else gets `/sr`.

To disable auto-detection (always redirect to default on first visit), set `localeDetection: false` in `routing.ts`. Generally leave it on — better UX.

## 8. Stanje — migracija je završena

Sve iz ranijeg plana migracije je izvedeno, pa ova sekcija opisuje šta stvarno postoji umesto koraka koje treba proći.

### Infrastruktura

`src/i18n/{routing,request,navigation}.ts` postoje, `withNextIntl` je u `next.config.ts`, a middleware je `src/proxy.ts` (Next 16 preimenovanje) i u njemu je dodatno geo pravilo: posetilac iz Srbije bez kolačića dobija `/sr` bez obzira na `Accept-Language`.

Root layout je `src/app/[locale]/layout.tsx`, ne `src/app/layout.tsx`. Jezik dolazi iz `params`, ne iz `headers()` — to je uslov da javni sajt ostane statički prerenderovan. Admin deo ima svoj root layout u `src/app/uvid/layout.tsx`, pa aplikacija ima dva root layouta i zato i `src/app/global-not-found.tsx`.

### Lokalizovani URL segmenti

`routing.ts` definiše `pathnames`, pa se interne rute razlikuju od onoga što posetilac vidi:

| Interna ruta | sr | en | ru |
| --- | --- | --- | --- |
| `/usluge/[slug]` | `/usluge/…` | `/services/…` | `/uslugi/…` |
| `/lokacije/[slug]` | `/elektricar/…` | `/electrician/…` | `/elektrik/…` |
| `/alati` | `/alati` | `/tools` | `/instrumenty` |
| `/privatnost` | `/privatnost` | `/privacy` | `/konfidencialnost` |
| `/uslovi` | `/uslovi` | `/terms` | `/usloviya` |

Svaki canonical, hreflang i sitemap URL se gradi preko `getPathname()` u `src/lib/seo.ts` — nigde se ne sklapa ručno.

### Sadržaj

Izabrana je Option B iz ranijeg plana: struktura je po jezicima.

```
src/content/<kolekcija>/<jezik>/<slug>.mdx
```

Kolekcije: `blog`, `usluge`, `lokacije`, `pravno`.

Dva pravila koja `src/lib/mdx.ts` proverava i obara build ako se prekrše:

1. **Ime fajla mora biti jednako `slug` polju** u frontmatteru.
2. **`key` polje povezuje prevode.** Slugovi se razlikuju po jeziku namerno — `zasto-fid-iskace` / `why-rcd-trips` / `pochemu-srabatyvaet-uzo` — jer je slug signal za rangiranje. `key` je jedino što može da odgovori u kojim jezicima unos postoji, a od toga zavisi hreflang.

**Nema fallback-a na srpski.** Prevod postoji samo ako fajl postoji; dok ne postoji, taj URL se ne generiše, nije u sitemapu i hreflang ga ne pominje. Prijaviti prevod koji ne postoji je gore nego ne prijaviti ništa.

Zbog lokalizovanih slugova, prebacivanje jezika na stranici sadržaja ne može samo da zameni prefiks. `buildSlugMap()` iz `src/lib/mdx.ts` se prosleđuje `LocaleSwitcher`-u kao prop, pa switcher zna da `/sr/blog/zasto-fid-iskace` na engleskom postaje `/en/blog/why-rcd-trips`. Kad prevoda nema, vodi na indeks sekcije umesto na 404.

### Interni linkovi u MDX-u

Pišu se u **internom** obliku — ime direktorijuma kolekcije plus slug tog jezika:

```md
[prerada elektro table](/usluge/elektro-table)
```

`src/components/mdx-components.tsx` to prevodi u next-intl `Link`, pa se renderuje kao `/sr/usluge/…`, `/en/services/…` ili `/ru/uslugi/…` zavisno od jezika teksta. Običan `<a>` bi izgubio prefiks i naterao middleware na redirect.

### SEO

Odrađeno: `generateMetadata` sa `alternates` na svakoj strani, sitemap sa hreflang alternativama po jeziku, i `LocalBusiness` JSON-LD. Detalji su u [`seo/README.md`](./seo/README.md).

Jedna namerna nedoslednost: `<html lang>` je `sr-Latn`, a hreflang je `sr`. To su dva različita mehanizma i ne moraju da se poklope — Google za hreflang dokumentuje jezik i opciono region, pa bi subtag za pismo mogao da dovede do toga da anotaciju odbaci.

## 9. Common pitfalls

- **Forgetting `setRequestLocale`** in layouts/pages causes next-intl to fall back to dynamic rendering, breaking static export. Call it as the first thing after validating the `locale` param.
- **Mixing `next/link` and `@/i18n/navigation`'s `Link`.** The first won't carry the locale; users hop to the default locale unexpectedly. ESLint rule worth adding: ban `next/link` and `next/navigation` imports outside `src/i18n/`.
- **Hardcoded `lang` attribute** on `<html>`. Always derive from URL locale.
- **String concatenation across translations**: `t("hello") + " " + name`. Always use a placeholder: `t("hello", { name })`. Word order differs across languages.
- **Russian without `many`.** `{count, plural, one {...} few {...} other {...}}` will show the wrong form for 5, 10, 25 in Russian. Always include `many`.
- **Using `Date.toLocaleString()` without a locale.** Renders differently per server timezone/locale. Use `useFormatter` or `Intl.DateTimeFormat` with an explicit locale and the `Europe/Belgrade` timezone.
- **Not testing `/`** — without `localePrefix: "always"` plus middleware matcher, hitting the bare root can 404. The matcher above handles this.
- **Cyrillic creep.** Serbian content is locked to Latin. If a translator submits Cyrillic, reject. (Future migration to dual-script means renaming the URL locale to `sr-Latn` and adding `sr-Cyrl`.)
